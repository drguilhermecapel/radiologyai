# REQ-115 — Registro medido com proveniência lida, não digitada

## Requisito

Todo registro medido DEVE carregar o sha do git lido do repositório, o `protocol_id`, o sha256 do manifesto do dataset calculado sobre todas as colunas exceto o escore (rótulo ausente distinto de negativo), o sha256 de cada arquivo de pesos calculado a partir do arquivo e o comando exato. A medição DEVE ser recusada quando o código que mede (escopo `MEASUREMENT_SCOPE`: `evidence/`, `evaluation/`, `calibration/`, esquema e protocolo do catálogo, `scripts/evidence_run.py`, o plano, `pyproject.toml` e `uv.lock`) tiver arquivo modificado ou não rastreado, salvo opção explícita, e nesse caso o registro DEVE trazer aviso de não reprodutibilidade.

No modo plano (`evidence/measured/plan.yaml`), o hash de cada arquivo de pesos DEVE ser conferido contra o manifesto do modelo quando o item o declarar, e a medição DEVE falhar se divergir. O razão (`evidence/measured/ledger.yaml`) DEVE listar o desfecho de TODOS os itens do plano — aprovado, reprovado, não elegível, falha, pendente ou excluído. Item pendente (conjunto incompleto) NÃO DEVE produzir métrica. Registro cuja condição não existe em `conditions.yaml` DEVE ser gravado em `measured/_awaiting_condition/` e NÃO DEVE entrar em `levels.json`. A sobrescrita do número de iterações do protocolo NÃO DEVE gravar na evidência do repositório. Os arquivos JSON gravados DEVEM satisfazer a regra R3 do `check_honesty.py` (hash de 64 hex na mesma linha da chave).

## Justificativa

Um registro sem como ser reproduzido é uma alegação. Relatar só o que passou esconde falhas e conjuntos subdimensionados; extrapolar um conjunto incompleto produziria um número que nenhum procedimento pré-especificado mediu. A cadeia sha do git → manifesto → pesos → comando é o que permite a um terceiro refazer a medição e obter os mesmos números.
