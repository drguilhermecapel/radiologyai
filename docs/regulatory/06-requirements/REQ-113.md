# REQ-113 — Aprovação no protocolo decidida apenas pelos limiares pré-registrados

## Requisito

`passes_protocol` e `failure_reasons` de um registro medido DEVEM ser calculados exclusivamente a partir dos números medidos e dos limiares do `protocol.yaml` carregado (elegibilidade mínima por paciente, barras de AUROC, IC, sensibilidade/especificidade, ICC, Dice). Não DEVE existir parâmetro, opção de linha de comando ou campo de entrada que force aprovação. Registro reprovado DEVE listar cada barra não atingida com o valor medido e o limiar. Registro abaixo dos mínimos de casos (protocolo §2) DEVE sair com `passes_protocol: null` (não elegível), com os motivos declarados: NÃO DEVE aprovar nem refutar a condição.

## Justificativa

O nível A ou C depende de `passes_protocol`. Se uma pessoa pudesse ligar esse campo, o nível voltaria a ser digitado — o defeito que o catálogo existe para impedir. Uma amostra pequena demais não é evidência contra o modelo; se contasse como reprovação, uma medição subdimensionada rebaixaria a D uma condição com validação publicada.
