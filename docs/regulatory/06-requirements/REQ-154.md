# REQ-154 — Fila de análises com resultado imutável e falha com motivo

## Requisito

Cada pedido de análise DEVE criar uma linha nova (`queued` → `running` → `completed`|`failed`); reexecutar NUNCA sobrescreve. A reivindicação DEVE ser atômica (um único worker vence). O resultado DEVE ser gravado uma única vez, exatamente como o pipeline o produziu, junto do sha256 desses bytes, e DEVE ser conferido contra esse hash a cada leitura (divergência ⇒ erro explícito). Falha de execução DEVE marcar `failed` com o motivo, sem resultado parcial; análise interrompida por reinício DEVE virar `failed` com motivo, nunca ser retomada ou completada em silêncio.

## Justificativa

Um resultado que pode mudar depois de exibido ou assinado torna a decisão irreconstruível (RISK-007); um resultado parcial preenchido quando o modelo falha é exatamente o defeito do legado (RISK-004).
